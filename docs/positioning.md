# 同类项目与 Beer Lens 的定位

查阅日期：2026-09-12。以下依据项目官方介绍，比较用途与产品方向，没有进行同一测试集上的性能或成本对比。

## 我们在解决什么问题

Beer Lens 面向“眼前这张酒单里，我现在应该选什么”。输入来自现场图片或对话，决策同时依赖酒款身份、可核对的背景资料、当次限制与个人偏好。长期希望形成两个可复用的成果：领域数据资产，以及经过案例验证的处理方法。

## 同类与相邻项目

| 项目 | 官方介绍的重点 | 对 Beer Lens 的启发与区别 |
| :--- | :--- | :--- |
| [Barley Lens / Brewlytics](https://brewlytics.ai/lens) | 从酒单、货架或酒罐照片识别啤酒，结合口味画像、评分与新鲜度信息推荐；查阅时标记为开发中、等待发布 | 最接近的场景参照。拍照与个性化本身不是独有能力；我们需要用中文实体处理、具体约束与可检查的案例证明自己的价值 |
| [Dify](https://github.com/langgenius/dify) | 通用 AI 应用平台，覆盖工作流、RAG、Agent、模型接入与运行观测 | 可借鉴执行可视化与运营反馈。Beer Lens 聚焦领域应用，现阶段不追求平台功能广度 |
| [RAGFlow](https://github.com/infiniflow/ragflow) | 以文档理解和检索增强生成为核心，结合 Agent 构建知识上下文 | 可借鉴资料处理与证据引用。Beer Lens 还需处理现场候选、菜单限制与用户品饮后的状态变化 |
| [Cocktail Cache](https://github.com/darth-dodo/cocktail-cache) | 根据家中已有材料提供鸡尾酒、无酒精饮品配方和制作建议 | 相邻的饮品决策场景。它围绕“已有材料可以做什么”，Beer Lens 围绕“现场菜单应该选什么” |

这些是定位比较，不意味着其他项目缺少某项技术，也不意味着 Beer Lens 已在识别、推荐质量或使用体验上领先。

## 值得持续投入的特色

1. **中文名称与实体对应。** 将中文、英文、别名与酒厂／版本信息一起核对；名称近似只是候选线索，不能直接当作同一酒款。
2. **点单过程的连续性。** 从图片到候选，再到预算、风格和口味筛选；保留当前酒单，让后续追问有明确对象。
3. **可验证的体验改进。** 保留输入、执行结果和失败案例，让测试检查具体字段、约束及记忆变化。
4. **数据与方法分开维护、共同迭代。** 数据记录事实与来源；方法记录适用前提、操作、反例与验证结果。

前两项已有代码基础，但仍有识别和解析缺陷；后两项已有调试与测试工具，完整反馈闭环尚未打通。当前实测边界见 [测试说明](testing.md)。

## README 的表达选择

首页按“场景 → 真实输入 → 项目特色 → 数据 → 上手 → 验证”组织，让第一次访问的人先理解用途，再找到运行和检查的入口。架构和运维细节移到开发文档。

数据统一表述为“我们自主整合并持续维护的领域数据资产”，突出整理、映射、匹配和质量维护的工作；在独立数据文档保留来源说明。截图或样本只展示真实材料；规划不包装成现成功能，自动断言通过数不包装成准确率。
