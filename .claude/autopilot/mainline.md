# Beer Lens 主线

## 目标
做能在酒吧使用的试酒师：用户在飞书发酒单照片，目标在 60 秒内收到整张酒单的知识解读和首轮选择建议，后续追问复用这张酒单的上下文。
识别是输入；验收看是否帮助用户理解每款酒的特点、适合谁、为什么值得喝，以及如何取舍。60 秒是待验证的产品目标，不是已达成指标。

- D2 2026-09-14：保留多个产品调研方向，关联 Notion 与 GitHub；白天由用户定方向，夜晚执行已批准任务。

- D4 2026-09-19：用户批准使用 Coding Plan 尽量完成购买决策修复、爬虫/数据集验证与改进，含实际工程评测。夜间定时仍未设定。

- D6 2026-10-22：用户明确主线为“试酒师”，不能把 OCR 复述、记录数或仅有酒名/度数视为完成。逐步补齐酒款、酒厂、风格、酒花与工艺知识，并支持代表作依据、口味适配和价格比较。缺具体酒款事实时，可用明确标注的风格通识解释；不能虚构原料、品饮经历或酒厂实价。本轮先交付设计、SP 草稿与验收用例，运行时升级按该标准分阶段实施。

- D7 2026-10-23：用户明确“调用 plan 做更新，你每六小时 check 一次”，批准按 D6 设计进入实现，并恢复本聊天的 Beer Lens heartbeat 为每六小时更新与验收。沿用只用套餐、失败即停；主代理负责范围、验收和串行集成。此授权替代 D6 的本轮仅设计阶段及旧调度限制，不扩大为无限重试、付费兜底或自动部署。
