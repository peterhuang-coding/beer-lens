# 数据资产

**我们自主整合并持续维护面向精酿场景的领域数据资产。**

这项工作围绕真实点单展开：将分散的酒款资料、中英文名称、酒厂与版本线索、评分记录和图片证据，组织成可查询、可核对、可持续补充的数据层。

## 我们积累的工作

| 层次 | 内容 | 作用 |
| :--- | :--- | :--- |
| 资料整合 | 多来源酒款字段与评分缓存 | 提供检索和核对的基础 |
| 实体对应 | 中文名称映射、别名、酒厂和版本匹配规则 | 减少名字相似却不是同一酒款的误匹配 |
| 场景证据 | 酒单、酒标和实际任务样本 | 检查从现场图片到候选的可靠性 |
| 质量维护 | 测试用例、失败记录与匹配检查 | 将错误转成明确的修复和补充任务 |

## 来源与存放位置

“自主整合”描述的是项目自身的组织、匹配和维护工作，不表示全部原始记录由我们原创。现有数据涉及 RateBeer 数据集、Untappd 缓存，以及项目维护的名称映射与测试材料；评分和第三方原始资料仍需按其来源理解。

| 位置 | 内容 |
| :--- | :--- |
| [`.beer-data/beer.db`](../.beer-data/beer.db) | 本地 SQLite 酒款资料与缓存 |
| [`.beer-data/lookup.py`](../.beer-data/lookup.py) | SQLite 查询入口 |
| [`lib/beer-agent/beer-db/`](../lib/beer-agent/beer-db/) | 数据查询、补全、别名与采集代码 |
| [`data/`](../data/) | 种子、配置和回归任务等项目数据 |
| [`public/test-assets/`](../public/test-assets/) | 酒单、酒罐和营销卡片测试图片 |

2026-09-12 本机只读检查的表行数为：

| 表 | 行数 |
| :--- | ---: |
| `beers` | 14,228 |
| `untappd_cache` | 50,629 |
| `beer_cache` | 0 |

这是一个本地快照，不是实时统计。不同表可能覆盖同一酒款，不能相加当作去重酒款数，也不表示全部记录已人工核验。

## 数据如何参与回答

图片或文本先提供候选名称及线索，数据层查询可能的酒款，匹配逻辑结合酒厂和版本等证据判断是否可以引用。匹配不足时应保留缺失信息；模型猜测不应升级为酒库事实。

这一原则已有代码支持，但当前仍存在 OCR 和实体解析问题，见 [测试与已知缺口](testing.md)。一个回答返回了酒名和评分，并不足以证明它对应正确酒款。
