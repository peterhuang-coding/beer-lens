## 范围与来源限制

- 仅使用公开网页/搜索索引/缓存快照（2026-10-21 核对），`access` 一律为 `web_index_or_cache`；部分页面非直连成功（如 #7 仅有索引证据、#14 官方在线页是无内容 JS 空壳、#16 直链 429 未重试）。
- **不含任何可用评分/UT ID**：历史评分（如 3.93/68496、4.38/181 vs 4.289/943）时间与版本口径不确定，一律不写成评分字段；#12 的冲突快照仅作为分歧记录保留在 `field_disagreements` 中。
- 菜单转录价格/容量是 **2026-10-20 的单点观察**（`observation`，CNY），不是当前库存、不是零售基准；菜单照片无公开 URL，未杜撰任何 sourceURL。
- 所有来源文本按不可信数据处理，中文描述为意译，非原文搬运。

## 本地导入（先在备份/预演库执行）

```bash
python3 scripts/import-menu-supplement.py \
  --db /path/to/beer.db \
  --catalog data/menus/elnido-2026-10.json
```

行为：

1. 先完整校验 17 条载荷并预检既有表结构（`beer_cache`、`beers`、`untappd_cache` 须存在且含必需列），任何不满足都在写事务**之前**失败、零改动。
2. 单个事务内：新建（如不存在）`menu_supplements(menu_id, entry_id, payload, PRIMARY KEY(menu_id,entry_id))`，写入全部 17 条完整 JSON（可重复导入，按主键 upsert）。
3. 仅 15 条 confirmed 身份写入 `beer_cache`：`rating/ratings_count` 为 NULL，`source_platform='curated_public_menu'`，`verified=1`，`verified_at='2026-10-21'`；若 `beers`/`untappd_cache`/`beer_cache` 已存在相同 casefold 名称+酒厂则跳过，绝不更新或删除既有行；不迁移旧表结构。#11/#17 只存在于 `menu_supplements`。
4. stdout 输出真实计数 JSON（`beer_cache_inserted` / `beer_cache_preserved` / `menu_rows_written` 等）；失败时 stderr 输出错误 JSON 并以退出码 2 结束。

## 运行时接地（图片菜单问答）

`lib/beer-agent/menu-supplements.ts` 提供纯函数 `groundMenuSupplements`：规范化精确名称或显式别名；输入含酒厂时严格限定酒厂，缺酒厂时仅允许唯一名称命中；绝不以酒头号/menuIndex 匹配。命中后保留 OCR 的价格/容量/displayName/menuIndex，补充规范风格/ABV（6.66↔6.7、19.25↔19.2 视为舍入容差，9↔9.1 仍为冲突），来源分歧一律打标，所有命中行清除继承的旧评分/ID/链接，并附一条 `social_web` 证据（中文简介、来源链接、日期范围与冲突说明）。快照价格永不注入证据或其他菜单。`provider.ts` 在既有活动目录接地之后读取一次本补充并应用。
