# Beer Lens 修复与复测 — 2026-09-11

上一轮报告中的会话串酒单、预算和风格失效、图片错误路由、候选重复及评分错配已修复并复测。仍不能宣称全部产品验收通过：El Nido 小字实体识别、旧测试期望及缺失图片仍有缺口。

基线为 `b636deb`，修复分支为 `codex/live-qa-fixes`。真实请求使用同一个 `127.0.0.1:3000` 服务及现有模型配置。离线测试与真实模型结果分开记录；没有修改 344 条或 60 条原有期望来提高通过率。

## 改动与行为证据

- **会话记忆**：浏览器使用随机匿名 cookie；完整用户 ID 与会话 ID 一起哈希。长期口味仍按用户保存，活跃酒单按会话保存。新菜单替换旧菜单，识别失败也清除旧候选；保留全量酒单、价格、容量、编号、评分来源和 OCR 证据。
- **当前要求**：图片、文本及追问共享候选决策路径。预算、风格、酒精度进行硬筛选，未知价格不能冒充预算内。预算缩紧不会删除原菜单，放宽预算后可重新选择；新菜单不继承旧约束。原图最低价 55 元，追问预算 50 元时不再推荐 85 元酒款。
- **图片事实**：携图的瓶罐问题进入视觉酒标技能。LA LOVE 罐图识别出 Monkish、LA LOVE、8.5%、473ml；无清晰生产日期时不推测日期和新鲜度。营销卡保留 Lunch、Dinner 两个名称及 7%/8.2% ABV，推荐列表不重复列出同一候选。
- **评分匹配**：发现候选与附加评分采用不同门槛。完整名称、明确酒厂及版本必须一致；Lunch 不得借 Liquid Lunch 的分数。DDH 别名保留限定词，批次/口味映射到系列的旧别名仅用于发现，不可证明具体酒款评分；酒厂均分仅作背景。未核验评分保持未知，图上广告评分不当独立事实。
- **路由与运行**：恢复公开 intent 名称，修复图片、品饮反馈、历史查询、偏好更正的优先级和记忆写入接线。没有菜单的指代问题要求补充上下文。提供者临时错误有最多三次尝试及统一截止时间；代理失败实际恢复原 dispatcher。酒标视觉限时 120 秒，知识回答限时 45 秒。
- **验收工具**：图片 benchmark 覆盖两个 API 的真实 JSON/SSE、实体、价格、ABV、追问、cookie 连续性及会话隔离；缺图不能 PASS。并行回归报告使用 UUID，避免同毫秒分片覆盖。页面去掉写死的历史测试通过数。

评审涉及记忆接线、约束、实体、评分来源、OCR 标题、别名版本及提供者重试。提出的问题均经修改和相关测试复核；最终增量评审没有未解决的 P1/P2 代码问题。这个结论不代表模型识别准确率已经达标。

## 仍未通过或未覆盖

1. **El Nido 小字 OCR**：两个 API 最终均返回 19 个啤酒/啤酒冰沙候选，排除两款明确非啤酒饮料，IPA 推荐约束生效，LA LOVE 不重复。但 Monkish 仍读成 Morshik；此前还观察到 Abraxas 2025 被读成 Abyssus 2025。原始 OCR 也读错时，不能凭酒库猜改。保留原文与酒厂未核验提示，下一步需要独立区域重读及人工标注样本。
2. **测试标准**：`data` 与 `public/data` 的旧回归仍有 85 条期望字段差异。部分旧期望与最新用户问题不一致，无上下文用例也需要明确标准；本轮没有批量重写这些期望。完整原断言结果如上，不能声称旧回归全绿。
3. **缺图**：`menu-clear.jpg`、`bottle-label.jpg`、`glass-beer.jpg`、`menu-blurry.jpg` 仍缺失，g005 也依赖缺失图片。`tap-list.jpg` 与 `测试图片.jpg` 内容相同，只算一张独立图。未用其他图或生成图冒充这些样本。
4. **原有升级主线**：新数据导入与查缺补漏自动化、runBeerDecision P0–P3、旧 Stage2 台账不因本轮修复而被标记完成。
